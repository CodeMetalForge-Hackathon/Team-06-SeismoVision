# Team 6 project guidance

- Read `README.md` and `docs/project/earthquake-stability.md` before changing project scope.
- The Raspberry Pi implementation is owned by a teammate. Do not replace, reorganize, or invent that code without coordinating with its owner.
- Distinguish implemented behavior, planned behavior, and research ideas in every README, demo, and PR.
- Do not describe camera output as proof of safe entry or as a validated collapse prediction. State measured motion, uncertainty, and the need for qualified building assessment.
- Use `docs/research/evidence.md` for sourced technical claims. Do not copy a numerical threshold from a paper to a different building or demo model.
- Keep the full brainstorming Google Doc intact. Add project-specific updates only to its Earthquake Stability tab; the dated PDF in this repo is an archive, not the live source.
- Keep credentials, private keys, and unapproved personal or site footage out of Git. The repository is private, but collaborators and organizers may see its contents.
- Before claiming code works, run its documented build or test commands and report the observed result. Update `code/README.md` when implementation lands.
- Keep changes focused and push early enough for the Sunday noon Eastern submission cutoff.
